# 项目任务：256 输入下的 sigma4／2 对照

准备日期：2026-10-23。目标是假设检验：保留256输入与1802条正常特征库，减小异常图高斯平滑强度，能否提高定位IoU，同时不降低缺陷像素召回、不增加正常图像素误报，并保持接近原方案的推理成本。正式结果须由使用者手动运行得到。

## 现在怎样运行

1. 在 `01运行入口` 双击 **运行平滑强度对照实验.cmd**。
2. 依次完成 `CALIBRATE`（正常校准）、`EVALUATE`（开发评价）、`BENCHMARK`（三轮测速），随后生成配对图和完整性记录。
3. 看到 **SMOOTHING_COMPARISON_COMPLETED** 和 **Exit code: 0**，再打开新目录的 `结果摘要.txt` 与 `可视化/`。
4. 新结果全部保存在 `04实验结果/06平滑强度对照/smoothing_comparison_日期_时间/`。程序失败会留下 `status.json` 和 `error.log`，目录存在本身不表示实验完成。

无需重建库、训练模型或修改已有代码参数。入口提供 `--check-only`，只检查模型、数据、历史异常图和配置身份，不进行图片前向。

## 控制条件

两组都使用相同256输入、原检查点中的冻结骨干、1802×384正常特征库、参考检索与图像评分。唯一主动改变的是 anomalib2.2.0 `AnomalyMapGenerator` 的sigma：参考4、候选2，对应33×33和17×17高斯核。sigma以输入图像像素为单位，不是原图尺寸单位。

仅用原44张正常校准图和45张开发图（正常8、异常37），70张保留测试不读取、不评价。已有建库176张不重新提取特征。

图像分数与高斯平滑独立：图像阈值固定为已记录的q975阈值 `13.575581574440001`，验证两组分数和判断不变。像素阈值由每组的44张正常异常图分别按99.5%分位数确定，仍用原图坐标、`linear`和严格 `>`；不直接沿用sigma4的像素数值阈值给sigma2。新阈值在开发评价前保存。

sigma4会核验保存的正常与开发分数、异常图和像素阈值，以确保参考流程复现。完整运行前后检查原模型、特征库、历史文件与阈值选择记录保持不变。不会保存一份重复模型权重；新配置明确引用原检查点。

## 怎样判断是否值得保留

- 全部37张异常图与小面积组3张的逐图平均IoU、F1、AP及配对变化。
- 总体缺陷像素召回率，小面积组像素召回率，正常图片上的像素误报率。
- 两组图像判断保持不变；像素汇总AUROC/AP与Precision/Recall/F1/IoU也保存。
- 全模型推理平均/P95耗时、每轮平均值、每次原始耗时和PyTorch分配显存峰值。

为落实“保住召回”，本轮的保守描述性检查要求：总体与小面积组召回都不低于sigma4；正常图像素误报率不高于sigma4；总体及小面积组平均IoU均提高；图像判断不变。没有在看结果后偷偷放宽门槛。

这些条件只用于明确取舍，不会自动替换现有配置。成本以sigma2/sigma4的实际比例报告，不把微小计时波动解释成确定加速。即使IoU提高，如果召回降低，也会明确标记条件未满足，并记录增加的FN。

面积组按原图中的GT总缺陷面积比例固定：小于0.1%为0张，0.1%至小于1%为3张，至少1%为34张。它不是独立连通缺陷尺寸；三个案例不足以证明对极小缺陷普遍有效。

## 测量与可视化

一个模型驻留GPU，仅切换参考异常图生成模块；模块创建/切换在计时之外，未使用的模块在CPU。每轮每个sigma预热10次，再测45张图；顺序4→2、2→4、4→2，各135次计时。batch=1，输入在GPU就绪后计时，前后同步CUDA，范围包括完整模型前向与原图GPU插值；解码、预处理、CPU/GPU传输、指标计算及写盘不计入。

显存是 `max_memory_allocated`，另记录减去前向前分配量的增量，不是整张显卡或整个进程的总占用。

配对图选择固定小面积组全部3张，加sigma4基线IoU最低的5张（去重）。图中显示原图、GT、两种热图及掩码，红线表示GT轮廓；热图用各自像素阈值归一化，仅用于显示，相同颜色不代表相同原始距离。所有45张图的数值变化保存在配对报告中。

## 输出文件

| 文件 | 内容 |
|---|---|
| `config.json`、`preflight.json`、`split_manifest.json` | 设置、代码和原产物哈希、数据身份 |
| `sigma4/`、`sigma2/` | 各自配置、校准分数/阈值、原图尺寸异常图、逐图预测、评价报告 |
| `paired_localization.json` | 明确标记sigma4/sigma2的逐图差值与面积分组 |
| `timings.json` | 每次计时与分配显存原始记录 |
| `report.json` | 原流程复现、质量条件、成本比例与完整汇总 |
| `可视化/`、`visualization_index.json` | 配对图片及选择清单 |
| `结果摘要.txt` | 优先阅读的中文结果 |
| `status.json`、失败时的 `error.log` | 完成/失败状态与诊断 |

这是根据已见分辨率结果提出的开发阶段后处理消融，未提出新算法，也不证明泛化提升。平滑可能不是定位外扩的主因；减少平滑也可能让噪声更多、缺陷覆盖变差。结果不改善时保留证据，再决定是否改变方法。
