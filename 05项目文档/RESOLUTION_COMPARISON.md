# 项目任务：256 / 512 分辨率对照

准备日期：2026-10-23。本次要回答：在相同数据划分、骨干权重和特征库容量下，把输入从 256×256 提高到 512×512，能否改善小缺陷定位，代价是多少？需要实际运行后才能判断是否有效。

原始 256 基线继续作为参考。两种配置均使用 anomalib 的原始检索流程；此前分块检索的实验结果单独保留。本次代码、参数和启动入口属于实验准备，输入预检或合成测试通过不能代替真实开发集结果。

## 你现在怎么运行

1. 打开项目里的 `01运行入口`，双击 **运行分辨率对照实验.cmd**。运行期间尽量关闭游戏等占用显卡的程序。
2. 终端依次显示四个阶段：`BUILD512`（构建 512 特征库）、`CALIBRATE`（正常图校准）、`EVALUATE`（45 张开发图评价）、`BENCHMARK`（三轮测速）。建库可能比此前检索对照耗时更长。
3. 看到 **RESOLUTION_COMPARISON_COMPLETED** 和 **Exit code: 0** 后，打开 `04实验结果/05分辨率对照/resolution_comparison_日期_时间/结果摘要.txt`。
4. 优先查看中文摘要与 `可视化`。若运行报错，保留终端信息；目录已创建本身不能证明实验完成。

此入口会新建一份实验结果。实际建库和图片评价由你手动启动。`--check-only` 只检查输入和环境，不执行实际建库、图片前向或开发集评价。显存不足会明确报错，不自动降低分辨率、库容量或改变实验协议。

## 对照条件

| 条件 | 256 参考配置 | 512 对照配置 |
|---|---|---|
| 输入尺寸、精度 | 256×256、float32 | 512×512、float32 |
| 骨干与层 | 原检查点中的 ResNet18，layer2 / layer3 | 加载相同骨干权重，使用相同层 |
| 正常建库图片 | 固定 176 张 | 同一批固定 176 张 |
| 特征库 | 复用原检查点中的 1802×384 库 | 从新的局部特征中用 anomalib KCenterGreedy 选出恰好 1802×384 |
| 最近邻与评分 | 原参考流程，k=9 加权图像分数 | 相同原参考流程与评分 |
| 图像阈值 | 正常校准分数的 97.5% 分位数 | 本配置正常校准分数的 97.5% 分位数 |
| 像素阈值 | 正常校准异常图的 99.5% 分位数 | 本配置正常校准异常图的 99.5% 分位数 |
| 评价范围 | 同一批 45 张开发图、原图坐标 | 同一批 45 张开发图、原图坐标 |

提高分辨率后，候选特征更多。两者固定库容量为 1802 个向量，因此抽样比例不同，不能把这项实验写成“两种分辨率都采用 1% coreset”。512 先分批提取特征，再选择 coreset；随机种子和建库设置写入配置。

44 张正常校准图与 45 张开发图互不混用。两种分辨率的阈值分别由对应的正常校准分数确定，不把 256 的分数阈值直接搬到 512。256 会核验原始校准记录及像素阈值，并复用已经记录的 97.5% 图像阈值（`13.575581574440001`）；原基线的 95% 阈值及历史文件保留。70 张保留测试不参与前向、阈值选择或评价。

## 怎样评价“小缺陷”

定位指标统一在原图 700×700 坐标计算。主要看异常图片逐图的 **IoU、F1、AP**，再对这些逐图值取平均，避免仅看像素汇总时大面积缺陷占据主要权重。每张图还保存 512 相对 256 的指标变化，便于找出受益和退化样本。

分组规则在实验前固定为：人工标注的缺陷像素并集面积 ÷ 整张图片面积。根据已保存的开发集标注面积记录，37 张异常图的分组是：

| GT 面积占比 | 异常图片数 | 解释 |
|---|---:|---|
| 小于 0.1% | 0 | 指标记为 `null`，不能据此声称验证了极微小缺陷 |
| 0.1% 至小于 1% | 3 | 本次重点查看的小面积组，样本很少，只能做探索性比较 |
| 大于等于 1% | 34 | 同时观察较大面积缺陷是否退化 |

这是一张图上全部标注区域的总面积比例，不是每个独立缺陷连通区域的面积。当前最小图片级比例约为 0.436%，所以“较小面积缺陷”与“极微小缺陷”需要区分。分组只用于评价，不用于建库或挑选阈值。

同时报告图像 AUROC / AP、固定阈值下的误报漏检，以及汇总像素 AUROC / AP、Precision / Recall / F1 / IoU。正常图没有缺陷标注，不并入异常图的逐图定位平均；其像素误报仍需单独关注。单独查看小面积组 3 张图，并结合全部 37 张异常图的配对结果判断，不凭某张好看的热图下结论。

## 可视化怎么读

保存配对的原图、人工标注、256 / 512 异常图和各自阈值下的预测掩码。自动列出小面积组全部 3 张，以及 256 基线 IoU 最低的 5 张（重叠时只保存一份），连同指标一起检查。全部异常图的改善与退化情况在配对报告中统计。

两种配置原始异常分数的尺度可能不同。热图使用明确标注的阈值归一化刻度辅助比较，“1”对应各自像素阈值；相同颜色表示相对各自阈值的程度，不表示原始距离相同。判断定位好坏仍以人工标注和二值掩码为准。

## 资源成本怎样测

batch=1，每个配置每轮先预热 10 次，再对 45 张开发图计时。共 3 轮，顺序按 256→512、512→256、256→512 交替；每个配置累计 30 次预热和 135 个计时样本。每段只让一个配置的模型驻留 GPU，模型切换在计时之外，避免另一模型污染显存分配峰值。

输入已在 GPU 上就绪后开始计时，前后同步 CUDA；范围包含完整模型前向和回到原图尺寸的 GPU 插值。解码、预处理、CPU/GPU 传输、指标计算、可视化和写盘不计入，所以这不是从打开图片到显示结果的总延迟。

保存平均 / P95 耗时、每轮平均值和每次原始记录。显存记录 PyTorch 分配的绝对峰值，以及峰值减去前向调用前分配量的增量；二者均不是整张显卡或整个进程的总占用。

512 的新建库耗时和显存峰值另行记录。256 复用历史库，无法从此次运行得到可直接比较的 256 建库耗时，因此对应字段留空；不把“载入旧模型”当成“256 建库时间”。

## 会生成什么

| 文件或目录 | 内容 |

## 结果能支持什么结论

这是一项单类别、单随机种子的开发实验。分辨率提高会同时改变特征采样密度、相对原图的感受野以及 coreset 候选分布；默认平滑 sigma=4 仍以输入像素计量，其在原图中的作用范围也会变化。因此结论是这两套输入分辨率配置的整体比较，不能把所有变化只归因于“更多像素”。

只有实际结果出来后，才能判断 512 是否值得保留。定位改善有限、误报增加、耗时增加或显存开销过大，都应完整记录。如果小面积组只有少数样本改善，下一步需要扩大类别或增加重复实验验证，再决定最终方案。
