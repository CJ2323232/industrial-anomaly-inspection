建议把 **WideResNet50 / 256 / sigma4，全局像素阈值2.1031780243** 作为下一阶段定位验证的主候选。整图阈值沿用该模型原规则，不在本次改动。

## 为什么不直接选2.127015

2.127015是新骨干在严格等总体召回对照中的工作点：汇总IoU0.6941、平均IoU0.5013、FP985275，但小面积组漏64个像素（color/001漏63、bent/002漏1）。本推荐增加“小缺陷全部覆盖”的条件，允许更宽一些的掩膜，换取这3张已知小缺陷的完整覆盖；没有声称未知小缺陷也一定不漏。

## 每个指标怎样理解

- Recall：真实缺陷里找到了多少；95.9%意味着约4.1%的缺陷像素漏圈。
- IoU：圈出区域与真实缺陷的交并比；同时惩罚多圈和漏圈。这里主指标把全部45张图的像素计数先累加。
- Precision：圈出的区域里有多少是真的缺陷；其余为误圈。
- FP：误圈的正常像素总数。误圈面积占比=FP/全部45张图的像素数，不是FP/正常像素数。
- 平均IoU：对37张异常图等权平均；用于检查总体像素指标是否被大缺陷主导。

## 必须接受的具体代价

- WideResNet50原实测处理时间约为同次ResNet18的2.43倍（7.015→17.047ms），PyTorch分配显存峰值38.51→146.45MiB。调像素阈值不会消除这项成本。
- 原整图误报仍为1/8（good/005），基线为0/8；两者整图漏检均0/37。本次优化的是定位掩膜，不能写成整图误报也改善。
- 个别缺陷边界仍退步；主扫描报告提供所有逐图结果及退步案例。新骨干14/37张AP下降，8/37张即使逐图选择最佳阈值，IoU仍不到0.5，说明单调阈值不是全部问题。

## 如何使用这项选择

将它作为一个待独立验证的开发候选，保留原基线作对照。这里的最优使用了开发GT，既不是正式部署校准，也不是最终泛化结论。网络、模型权重和现有配置均未修改，70张保留测试图仍未访问。
如果目标只追求同总体召回下更紧的掩膜，主扫描表中的2.127015更合适；本项目强调小缺陷覆盖，因此主推荐采用上面的约束最优工作点。

## 主推荐的逐图收益和退步

在小缺陷覆盖约束下，37张异常图中21张IoU提高、16张下降，不能说每张图都变好。小面积组平均IoU 0.2379→0.2270，虽然三张已知小缺陷均完整覆盖，但边界精细度没有提升；这正是采用较宽掩膜保护召回的代价。

- `scratch/000`：IoU 0.476→0.658，漏圈2791→1273，误圈4390→2905。
- `color/001`：IoU 0.160→0.219，误圈14498→9888，缺陷均完整覆盖。
- `color/000`：IoU 0.236→0.155，误圈6925→11599，缺陷均完整覆盖；这张仍是明确退步案例。
- `bent/014`：IoU 0.441→0.358，漏圈448→0，但误圈5595→9360；用更多多圈面积换取覆盖。

因此主推荐是“总体像素召回和汇总定位改善、保护已知小缺陷覆盖”的方案，而不是“小缺陷边界普遍更准”的方案。若接受三张图共64个缺陷像素未覆盖，2.127015可将小面积平均IoU提高到0.2444、总体平均IoU提高到0.5013；该取舍在完整阈值报告中单列。


# 阈值扫描与当前方案选择

**结论范围：现有45张开发图、5种已保存配置。未训练、未推理、未修改网络结构，未访问70张保留测试图。**

## 明确推荐

按“先达到原基线95.904148%缺陷像素召回，再选汇总Pixel IoU最高”的规则，当前开发集定位优先方案是：**WideResNet50 / 256 / sigma4，全局像素阈值2.1270151138**。
相对同召回基线：汇总Pixel IoU 0.6637→0.6941，平均IoU 0.4707→0.5013，误圈减少14.24%。37张异常图中27张提高、10张下降。

## 每个数据代表什么

| 数据 | 计算方法 | 直观含义 |
|---|---|---|
| Pixel Recall | TP/(TP+FN) | 真实缺陷像素中覆盖了多少；越高越少漏圈。大缺陷像素权重更大，不代表每张图召回相同。 |
| Pixel IoU（汇总） | TP/(TP+FP+FN) | 预测区域与真实缺陷的交并比，漏圈和误圈都会拉低；全部图先累加计数。 |
| Pixel Precision | TP/(TP+FP) | 圈出的区域中有多少确实是缺陷；越高越少把正常区域圈进去。 |
| FP像素 | 正常GT且分数大于阈值的像素数 | 多圈了多少原图坐标像素，含正常图和异常图中的正常区域。 |
| 误圈面积占比 | FP/(TP+FP+FN+TN) | 多圈区域占全部45张图总面积的比例。与FPR分母不同。 |
| 正常像素FPR | FP/(FP+TN) | 所有正常像素中有多少被误圈。逐阈值结果也给出这个指标。 |
| 预测区域污染率 | FP/(TP+FP) | 圈出区域里有多少是正常区域；等于1−Precision。 |
| 平均IoU | 37张异常图各自IoU的平均 | 每张图一票，降低大缺陷主导总体指标的影响。正常图不按IoU=1计入。 |
| AP | 连续分数下的精确率−召回率排序指标 | 不依赖选定的单一阈值，但不直接等于边界IoU。 |
| 小面积组 | GT总面积小于全图1%的3张图 | 单独检查已知小缺陷，样本很少，不能外推普遍结论。 |
| 像素阈值 | raw score > threshold | 控制掩膜，不是概率；也不是整图判定阈值13.576。不同骨干的分数尺度不可直接比较。 |

以本次主推荐为例：每100个真实缺陷像素覆盖约95.90个；每100个圈出的像素中约71.53个是真缺陷；误圈区域占全部图像面积4.47%。

## 阈值问题还是分数定位问题

阈值运行点影响有证据；仍存在逐图分数排序/定位限制。不是只换阈值就能解决全部低IoU；结构的独立因果收益证据不足。

原正常阈值下，两种骨干平均IoU：0.4707→0.4650；等召回后：0.4707→0.5013。模型与分数图不变，说明工作点会影响此前的优劣判断。
新骨干平均AP：0.7943→0.8133；但有14/37张的AP下降。不能说所有图的排序都更好。

## 后处理一致性审计

两骨干配置、检查点中的平滑核、生成脚本哈希已核对一致：
- 相同256输入、ImageNet输入归一化；不对异常分数做min-max或概率归一化。
- 相同32×32得分网格、nearest上采样至256、sigma4的33×33高斯平滑（reflect/same），再bilinear映射至原700×700，align_corners=False。
- GT保留原700×700二值掩膜，图/掩膜哈希和路径对应，不插值、不裁剪、不旋转。
- 保存的是阈值化前的float32连续图；扫描仅做严格大于比较，不加形态学、连通域或自适应后处理。
- sigma2、512和分块方案故意改变平滑/分辨率/裁剪合并，作为不同完整配置比较；不能将它们的收益归因于换骨干。
- 原始平滑前patch分数未保存，无法完整重放历史后处理；当时库文件未逐个哈希，当前2.2.0实现、记录的工程代码与保存的核共同支持本次审计。
- 换骨干还换了预训练权重和特征维度，不能据此隔离“网络结构本身”的因果收益。
