## 你现在做什么

1. 在项目文件夹双击 **运行检索对照实验.cmd**。不需要先运行教学入口，也无需重新建库。
2. 窗口依次显示 `CORRECTNESS`（45 张图的完整流程对照）、`WARMUP`（两种实现预热）、`BENCHMARK`（三轮计时）。运行时尽量暂停游戏或其他占用 GPU 的任务。
3. 看到 **RETRIEVAL_COMPARISON_COMPLETED** 与 **Exit code: 0** 表示实验执行结束；是否值得采用分块，还要看结果中的兼容检查和成本数据。
4. 打开 `experiments/retrieval_comparison_日期_时间/结果摘要.txt`，将内容或终端截图发回。失败时保留窗口中的完整报错。

## 改动范围

新模块 [retrieval_backend.py](../scripts/retrieval_backend.py) 在原 PatchCore 模型上切换最近邻实现，支持局部特征的 1-NN 和图像加权评分所需的 k-NN（当前 k=9）。骨干、预处理、1802 个库向量、图像加权评分、异常图生成和平滑仍使用已有参考流程。两种实现使用同一检查点、float32 精度、相同距离公式；只改变距离矩阵的分块与最优候选合并方式。

此前教学代码使用直接差值距离和 float64 比较；本次单独新增与生产参考一致的 float32 范数展开后端，旧代码及其结果不修改。本次实现仍属于已有精确最近邻方法的工程实现，不是新算法。

默认查询块 128、库块 512，k-NN 跨块合并时保留最小 k 个距离及全局索引。k=1 的精确数值等距取最小索引，k>1 的等距顺序不保证与原 `topk` 一致。浮点运算形状改变也可能影响极小距离，因此必须检查后续完整输出。

## 固定哪些条件

- 仅用固定清单的 45 张开发图（8 张正常、37 张异常），70 张保留测试不参与预测、评价或调参。
- 不拟合新模型，不更新库。原模型和实验文件的哈希在运行前后核对。
- 同时报告原 95% 阈值与暂定 97.5% 阈值下的图像指标；后者精确值为 `13.575581574440001`，只用于这次实现替换对照。
- 像素阈值保持 `11.98109245300293`。本任务比较相同输入特征和评分规则的实现，不重新调整阈值来掩盖差异；如果行为不兼容，先定位原因。

## 检查什么

1. 原实现的重新推理能否复现保存的图像分数。
2. 两个后端的逐位置最近邻距离、支持邻居距离、完整图像分数和原图尺寸异常图是否在预设容差内一致（`atol=1e-4, rtol=1e-5`）。
3. 两种固定图像阈值下有多少张判断改变，像素掩码有多少个像素改变。数值差异小也可能跨过阈值，不能只看浮点容差。
4. 两个后端各自的图像 AUROC/AP、混淆计数、误报漏检和像素 Precision/Recall/F1/IoU；本次不重新计算 Pixel AUROC/AP。
5. 完整前向的平均/P95 耗时、各轮平均耗时、PyTorch 显存分配峰值与相对前向前的增量。

严格兼容门槛要求分数、异常图、搜索距离全部满足容差，原分数复现通过，且图像/像素判断均不变。门槛失败会保留完整差异与性能报告，标为需检查，不自动改用分块。达到门槛也只说明这 45 张开发图上的行为，不能证明所有输入等价。

## 耗时与显存的口径

两种后端各预热 10 次，对同一批 45 张图各测 3 轮，每种得到 135 个样本。逐图交替执行先后顺序，降低固定先后顺序的偏差。CUDA 在计时前后同步，使用墙钟时间，包含 Python 调用、骨干、检索、加权分数、异常图和原尺寸 GPU 插值。

图片解码、预处理、CPU/GPU 传输、指标计算和结果写盘在计时之外，因此数字不是用户从选图到结果显示的总延迟。输入在 GPU 上就绪后才计时，batch=1，保存每次原始耗时。

每次前向重置 PyTorch 峰值统计，记录 `max_memory_allocated` 和调用前 `memory_allocated`。绝对峰值包含常驻模型、输入和输出，增量为峰值减调用前分配量。它们不是整个进程/显卡的总占用，也不是根据矩阵大小估算的值。其它程序、温度和功耗状态仍可能影响结果。

## 会生成什么

| 文件 | 内容 |
|---|---|
| `config.json`、`split_manifest.json` | 运行设置、数据身份、代码与检查点哈希 |
| `prediction_comparison.json` | 45 张图片逐图分数、距离差异、判断变化、像素指标 |
| `maps/` | 两种后端的原图尺寸异常图，保存在同一个 npz 中 |
| `timings.json` | 每次前向的耗时和内存原始记录 |
| `report.json` | 正确性门槛、两种阈值下的指标和性能汇总 |
| `结果摘要.txt` | 中文结果摘要，优先查看这个文件 |

必须有 `report.json` 及终端完成标志，目录存在本身不代表实验完成。执行完成与优化成功分别记录。效果没有提升、分块更慢或预测存在差异，都属于有效实验发现。
