# 第二课：最近邻距离与分块检索

准备日期：2026-10-19。七项合成数据检查通过（含 CUDA 与 384 维参考公式对照），实际 CMD 的 `--check-only` 返回 0，见[入口检查记录](results/2026-10-19-neighbor-entry-check.json)。真实图片最近邻对照尚未运行，由使用者手动启动后记录；距离图也将在实际运行时生成。

## 今天的问题

第一课把一张图片变成了 1024 个、每个 384 维的局部特征向量。正常库有 1802 个同样维度的向量。现在要为每个查询向量找到距离最近的正常向量，并记录这个最短距离。

对某一个查询，先比较全部正常库向量，取最小距离；查看整张图时再观察这些最小距离哪些较大。不是寻找离查询最远的正常库向量。

## 先手算一次

为了便于理解，用两个数描述位置，真实特征则有 384 个数。

查询为 `(0,4)`，正常库有 A=`(0,0)`、B=`(3,4)`、C=`(9,9)`。

欧氏距离等于各维差值的平方求和，再开平方：

- 到 A：`sqrt((0-0)^2+(4-0)^2)=4`。
- 到 B：`sqrt((0-3)^2+(4-4)^2)=3`。
- 到 C：`sqrt((0-9)^2+(4-9)^2)=sqrt(106)`，约 10.30。

最近的是 B，最短距离为 3。程序从 0 开始编号，所以 B 的库索引是 1。

本课只用固定正常拟合集里的 `metal_nut/train/good/000.png`，与第一课相接，检查现有模型/正常库身份。它不重新建库，也不评价独立测试性能。

## 两种计算怎样对照

- 全量参考：用 anomalib 的距离公式一次生成 1024×1802 的距离矩阵，再对每行取最小值。
- 学习实现：自己编写查询与特征库的双层分块循环，用 PyTorch `cdist` 计算每块欧氏距离，保留当前最小值和对应库索引；遍历全部库，因此没有近似跳过候选。

默认每次处理 128 个查询、256 个库向量。分块只控制距离矩阵的大小，向量维度仍然是 384。

为了核对数值，两边将同一份 float32 特征转成 float64 计算距离。距离公式不同可能产生细小浮点误差，按预设 `atol=1e-6, rtol=1e-7` 比较；允许等距或近等距情况下参考索引不同，同时核对选中向量的实际距离。这不等于已验证整个原 float32 检测流程。

在 float64 下，1024×1802 矩阵需要 14,761,984 字节，128×256 距离块需要 262,144 字节。它们仅是单个距离矩阵的存储量，不含向量、输出、库内部临时内存。本学习脚本还会生成全量参考用于核验，因此不能把这些数字当作实测峰值显存下降或提速结果。

## 看结果时要分清

- 距离越大，表示这个局部特征离库内最近的正常特征仍较远；距离不是概率。
- 距离网格的亮色只表示本图中相对较大的值，正常图也有最大值，不能据亮色认定缺陷。
- 这里是特征网格距离，尚未做完整的加权图像评分、平滑和原图坐标还原；之前的 13.576 图像阈值不能直接用于这些局部距离。
- 库索引表示特征库的第几行。目前库中未保存每行来自哪张原图、哪个位置，不能据索引生成来源图片解释。
- 采用同一张拟合图片检查代码，不构成泛化性能证据；70 张保留测试继续封存。

关键代码见 [nearest_neighbors.py](../scripts/nearest_neighbors.py)。本课代码由 AI 辅助准备，独立实现分块遍历与最小值维护，底层距离计算使用 PyTorch。已有骨干、正常特征库和参考距离公式来自 anomalib；它仍不是完整独立实现的 PatchCore，也没有提出新的最近邻算法。

## 命令行入口

```console
python scripts/inspect_nearest_neighbors.py --baseline-dir PATH_TO_BASELINE --data-root PATH_TO_MVTecAD --check-only
python scripts/inspect_nearest_neighbors.py --baseline-dir PATH_TO_BASELINE --data-root PATH_TO_MVTecAD --output-root artifacts/learning
```

可通过 `--query-chunk`、`--bank-chunk` 修改分块大小；也支持 `--device cpu`。先完成默认运行，后续再比较分块大小，避免同时改变多个条件。
