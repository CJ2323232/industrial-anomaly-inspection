## 问题与假设

原图像阈值为 13.273050，三个正常开发误报分数为 13.291329、13.388172、13.508660。开发缺陷最低分数为 13.606969。在本次已见的 45 张开发图上，正常与异常排序可分，但原阈值仍有误报。

先检查图像校准策略的作用，保持模型、特征库、分数、数据划分和像素阈值不变。候选规则为正常校准分数的 95%、97.5%、99% 分位数，均使用 `linear` 定义和严格 `>` 判异常。实际阈值只从同一份 44 张正常校准图的分数计算。

这些候选规则是在观察开发错误后提出的，比较结果属于开发探索，不是独立最终测试，也不代表 PatchCore 特征算法有了创新。

## 运行

```console
python scripts/analyze_thresholds.py --baseline-dir artifacts/trusted_baseline_001 --check-only
python scripts/analyze_thresholds.py --baseline-dir artifacts/trusted_baseline_001 --output-root artifacts/analyses
```

替换为实际完成的基线目录。脚本核对模型／校准文件身份、固定划分、CSV 样本及标签身份，并要求保存的原始分数复现原 95% 规则和混淆计数。仅从校准和开发 CSV 读取分数，不打开任何工业图片或保留测试数据。

结果输出到新的时间目录：`threshold_comparison.csv`、`score_distribution.png`、`analysis.json`。正常校准、正常开发和异常开发分数在同一坐标中显示，标出各候选阈值。运行前后核对原模型和原实验文件哈希，拒绝在来源改变时报告分析完成。

## 怎样解释

提高阈值在固定分数上使误报不增加、漏检不减少。即使某条规则在这 45 张已见开发图上没有错误，也不能保证对未见样本同样有效。校准集中正常最高分高于部分开发异常分数，高分位数规则需要检查漏检代价。

本实验只改变图像决策，不改变连续分数排序，因此 AUROC 不变；像素阈值也未改变，预测白块不会自动消失。像素校准和定位精度需要独立实验。

70 张保留测试图仍封存。后续决定采用哪条规则属于开发选择，须在最终测试前明确冻结并记录。不能据本次开发探索直接声称最终检测性能提升。
